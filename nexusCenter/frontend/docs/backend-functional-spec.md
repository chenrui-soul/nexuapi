# NEXUS API 后端功能需求文档

版本：`v0.1`  
日期：`2026-08-17`  
状态：后端开发基线稿

## 1. 文档目标

本文件用于定义 NEXUS API 后端的产品功能、业务规则、接口边界、数据对象和阶段性验收标准，作为前端、后端、测试和运维共同遵循的开发契约。

NEXUS API 的核心定位是：为用户提供统一、安全、可计费、可观测的 AI 模型 API 接入服务，同时为运营人员提供模型渠道、路由策略、服务分组和系统状态管理能力。

## 2. 项目范围

### 2.1 用户侧能力

- 注册、登录、退出、验证码与密码重置
- 查看账户、订阅、余额和积分明细
- 浏览可用模型、价格、能力和服务状态
- 创建和管理 API 令牌
- 通过统一接口调用不同 AI 服务商模型
- 查看请求日志、用量、成本、延迟和错误信息
- 使用创作空间直接调用文本、图像、视频等能力
- 查看分组状态、系统通知和接入文档

### 2.2 管理侧能力

- 用户、角色和账号状态管理
- 上游渠道与模型配置
- 模型映射、计费倍率和路由策略配置
- 套餐、积分、充值和账单管理
- API 令牌与风险操作审计
- 请求日志、异常告警和渠道健康监控
- 系统参数、公告、通知和功能开关管理

### 2.3 暂不纳入首期

- 企业组织、多租户和复杂部门权限
- 发票、税务和企业合同管理
- 完整工单系统
- 自建模型训练与数据集管理
- 国际化结算和多币种支付

## 3. 用户角色

| 角色 | 主要权限 |
|---|---|
| 游客 | 注册、登录、查看公开模型与服务状态 |
| 普通用户 | 管理本人账户、密钥、余额、订阅和调用记录 |
| 运营人员 | 管理模型、渠道、分组、套餐、公告和用户状态 |
| 管理员 | 拥有全部运营权限，可管理角色、系统参数和审计日志 |

所有管理接口必须进行服务端权限校验，不能只依赖前端菜单隐藏。

## 4. 总体业务架构

后端建议划分为以下模块：

1. 认证与账号中心
2. 用户与权限中心
3. 模型与渠道中心
4. API 网关与中转服务
5. 路由与故障转移服务
6. API 令牌与额度控制
7. 计费、积分和账单服务
8. 订阅与套餐服务
9. 日志、统计与监控服务
10. 通知与系统配置服务
11. 管理后台接口

## 5. 认证与账号功能

### 5.1 图形验证码

- 服务端生成验证码内容和唯一 `challenge_id`。
- 验证码默认 4 位，排除 `0/O`、`1/I` 等易混淆字符。
- 有效期建议为 5 分钟。
- 同一验证码成功验证一次后立即失效。
- 连续验证失败达到阈值后强制刷新。
- 登录、注册和密码重置分别使用独立场景标识。
- 接口不能直接返回验证码明文；前端只接收 SVG、图片或 Base64 内容。

### 5.2 注册

- 用户提交账号名称、邮箱、密码、验证码。
- 邮箱必须唯一，并进行格式标准化与小写处理。
- 密码至少 8 位，必须同时包含字母和数字。
- 密码必须使用可靠的单向哈希算法保存，建议 Argon2id 或 bcrypt。
- 注册成功后可直接创建登录会话。
- 预留邮箱验证状态；首期可以通过配置决定是否强制验证邮箱。
- 记录注册 IP、User-Agent、时间和来源。

### 5.3 登录

- 支持邮箱、密码和图形验证码登录。
- 登录成功返回访问令牌或建立 HttpOnly Cookie 会话。
- 推荐使用短期访问令牌和可撤销的刷新令牌。
- “记住我”开启时延长刷新会话有效期；关闭时使用短期会话。
- 密码错误、用户不存在等情况统一返回“邮箱或密码不正确”，避免泄露账号是否存在。
- 连续失败时增加验证码、延迟或临时锁定策略。
- 记录登录成功、失败、退出和令牌刷新审计事件。

### 5.4 密码重置

- 用户先提交邮箱和图形验证码。
- 正式环境应向邮箱发送一次性重置码或重置链接。
- 重置凭证必须有有效期、一次性使用并绑定用户与场景。
- 新密码不能与当前密码相同。
- 重置成功后撤销该用户已有刷新令牌和敏感会话。

### 5.5 登录状态与退出

- 提供当前用户信息接口。
- 支持主动退出当前会话。
- 预留退出全部设备功能。
- 被禁用、删除或风控锁定的用户不能继续刷新会话。

### 5.6 认证接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/auth/captcha` | 获取图形验证码 |
| `POST` | `/api/v1/auth/register` | 注册账号 |
| `POST` | `/api/v1/auth/login` | 登录 |
| `POST` | `/api/v1/auth/refresh` | 刷新访问令牌 |
| `POST` | `/api/v1/auth/logout` | 退出当前会话 |
| `POST` | `/api/v1/auth/logout-all` | 退出全部设备 |
| `POST` | `/api/v1/auth/password/forgot` | 发送密码重置凭证 |
| `POST` | `/api/v1/auth/password/reset` | 重置密码 |
| `GET` | `/api/v1/auth/me` | 获取当前用户信息 |

## 6. 用户与权限功能

### 6.1 用户资料

- 用户 ID、账号名称、邮箱、头像、状态和注册时间。
- 当前套餐、积分余额和 API 使用状态。
- 支持修改账号名称和头像。
- 修改邮箱需重新验证身份和新邮箱。

### 6.2 用户状态

| 状态 | 说明 |
|---|---|
| `active` | 正常使用 |
| `pending` | 等待邮箱或管理员验证 |
| `suspended` | 临时停用，禁止登录和调用 |
| `locked` | 风控锁定 |
| `deleted` | 逻辑删除 |

### 6.3 权限

- 首期采用 RBAC：用户、运营人员、管理员。
- 权限点建议采用 `resource:action` 格式，例如 `channel:create`。
- 所有管理操作写入审计日志。

## 7. API 令牌管理

### 7.1 密钥能力

- 创建、查看列表、编辑名称、禁用、启用和删除 API 令牌。
- 密钥明文只在创建时展示一次。
- 数据库只保存密钥摘要、前缀和末尾识别信息。
- 支持设置有效期、额度、允许模型、允许分组和 IP 白名单。
- 支持设置每分钟请求数、每分钟 Token 数等限制。
- 系统密钥与普通用户密钥分开管理。

### 7.2 密钥状态

| 状态 | 说明 |
|---|---|
| `active` | 可正常调用 |
| `disabled` | 用户或管理员停用 |
| `expired` | 已过期 |
| `revoked` | 已撤销，不允许恢复 |

### 7.3 密钥接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/api-keys` | 获取当前用户密钥列表 |
| `POST` | `/api/v1/api-keys` | 创建密钥 |
| `PATCH` | `/api/v1/api-keys/{id}` | 修改名称、限制或状态 |
| `DELETE` | `/api/v1/api-keys/{id}` | 撤销密钥 |
| `GET` | `/api/v1/api-keys/{id}/usage` | 查询密钥用量 |

## 8. 模型与渠道管理

### 8.1 模型

- 模型名称、展示名称、服务商、能力类型和上下文长度。
- 输入输出类型：文本、图像、音频、视频或多模态。
- 支持流式输出、工具调用、结构化输出等能力标识。
- 配置公开价格、内部成本、倍率和可用状态。
- 同一公共模型可以映射到多个上游模型和渠道。

### 8.2 上游渠道

- 渠道名称、服务商类型、Base URL、凭证和代理设置。
- 凭证必须加密保存，日志中禁止输出完整密钥。
- 配置超时时间、并发限制、权重和优先级。
- 配置支持的模型映射。
- 支持手动启停和自动熔断。
- 记录成功率、平均延迟、P95 延迟和最近错误。

### 8.3 服务分组

- 分组名称、描述、倍率、面向用户范围和可用模型。
- 同一模型可以在不同分组中使用不同渠道、价格和服务等级。
- 用户或 API 令牌可以指定默认分组。
- 分组必须提供近期可用率、延迟和探测记录。

### 8.4 路由策略

- 按模型、分组、权重、优先级和渠道状态选择上游。
- 支持失败重试和备用渠道切换。
- 流式响应开始后原则上不进行跨渠道重试。
- 对超时、限流、服务商 5xx 等错误分别配置重试规则。
- 熔断后进入半开状态，通过健康探测逐步恢复。
- 每次路由决策记录渠道、模型映射、耗时和切换原因。

## 9. API 中转网关

### 9.1 鉴权

- 客户端通过 `Authorization: Bearer <API_KEY>` 调用。
- 网关验证密钥状态、用户状态、额度、模型权限和限流规则。
- 每个请求生成全局唯一 `request_id`。

### 9.2 首期兼容接口

优先实现 OpenAI 兼容协议：

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/v1/models` | 获取当前密钥可用模型 |
| `POST` | `/v1/chat/completions` | 对话与文本生成 |
| `POST` | `/v1/responses` | Responses 风格统一生成接口 |
| `POST` | `/v1/embeddings` | 向量生成 |
| `POST` | `/v1/images/generations` | 图像生成 |
| `POST` | `/v1/audio/transcriptions` | 音频转写，可作为后续能力 |

视频等异步任务建议使用：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/v1/videos/generations` | 创建视频任务 |
| `GET` | `/v1/videos/generations/{id}` | 查询任务状态 |
| `POST` | `/v1/videos/generations/{id}/cancel` | 取消未开始的任务 |

### 9.3 请求处理流程

1. 生成请求 ID。
2. 解析并校验 API 令牌。
3. 校验用户、模型、分组、额度和限流。
4. 标准化请求参数。
5. 根据路由策略选择渠道。
6. 转换为上游协议并发送请求。
7. 处理同步、流式或异步响应。
8. 统计 Token、时长、图片或视频等计费量。
9. 完成扣费或结算修正。
10. 写入请求日志、账单明细和监控指标。

### 9.4 幂等与重试

- 支持客户端传入 `Idempotency-Key`。
- 充值、创建异步任务等接口必须实现服务端幂等。
- 网关重试不能造成重复扣费。
- 只有确认上游未成功处理时才能安全重试非幂等请求。

## 10. 限流与额度控制

- 用户、API 令牌、模型、分组和 IP 可以分别设置限制。
- 支持 RPM、TPM、并发数和每日额度。
- 限流建议使用 Redis 原子操作或 Lua 脚本实现。
- 超限返回 `429`，并提供可选的 `Retry-After`。
- 异步任务需要单独限制排队数和进行中任务数。

## 11. 计费与积分

### 11.1 账户余额

- 区分永久积分、限时积分和订阅额度。
- 优先消耗最早过期的限时积分，再消耗永久积分。
- 余额变动必须通过不可篡改的账本流水记录。
- 用户余额不允许直接覆盖更新，应通过交易流水计算和校正。

### 11.2 计费维度

- 文本：输入 Token、输出 Token、缓存 Token。
- 图像：模型、尺寸、质量和数量。
- 音频：时长、字符或 Token。
- 视频：模型、分辨率、帧率和时长。
- 最终费用 = 基础单价 × 分组倍率 × 其他计费系数。

### 11.3 预扣与结算

- 长耗时或异步任务可先冻结预计额度。
- 请求结束后按实际用量结算，多退少补。
- 请求失败时根据失败阶段决定是否收费。
- 同一 `request_id` 只能生成一笔最终结算记录。

### 11.4 钱包接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/wallet` | 查询余额和余额健康度 |
| `GET` | `/api/v1/wallet/transactions` | 查询积分流水 |
| `POST` | `/api/v1/wallet/recharge-orders` | 创建充值订单 |
| `GET` | `/api/v1/wallet/recharge-orders/{id}` | 查询订单状态 |

支付回调必须验签、幂等并记录原始回调摘要。

## 12. 订阅与套餐

- 套餐名称、周期、价格、包含额度、并发、模型权限和其他权益。
- 用户只能存在一个当前生效主套餐。
- 支持未生效、生效、过期、取消和退款等状态。
- 套餐切换需明确立即生效或下周期生效规则。
- 订阅额度和充值积分分开核算。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/plans` | 查询可购买套餐 |
| `GET` | `/api/v1/subscription` | 查询当前订阅 |
| `POST` | `/api/v1/subscription/orders` | 创建订阅订单 |
| `POST` | `/api/v1/subscription/cancel` | 取消自动续订或订阅 |

## 13. 仪表盘与统计

仪表盘需要提供：

- 请求总数和趋势
- 积分消耗和趋势
- 成功率与失败数
- P50、P95 响应延迟
- 缓存命中率
- 模型、API 令牌和分组消耗排行
- 类型分布
- 余额和预计可用天数
- 最近调用记录
- 分组运行状态

建议由日志明细异步聚合到分钟、小时和天级统计表，避免仪表盘直接扫描原始请求日志。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/dashboard/summary` | 获取核心指标 |
| `GET` | `/api/v1/dashboard/trend` | 获取时间趋势 |
| `GET` | `/api/v1/dashboard/distribution` | 获取类型和模型分布 |
| `GET` | `/api/v1/dashboard/rankings` | 获取排行 |
| `GET` | `/api/v1/dashboard/recent-requests` | 获取最近调用 |

## 14. 调用日志

### 14.1 日志内容

- 请求 ID、用户 ID、API 令牌 ID
- 请求时间、完成时间、总耗时
- 公共模型、上游模型、渠道和分组
- HTTP 状态码和平台错误码
- 输入、输出与缓存 Token
- 计费数量、费用和倍率
- 是否流式、是否重试、重试次数
- 客户端 IP 和 User-Agent 摘要
- 上游错误摘要和路由切换原因

默认不保存完整提示词和响应内容。若业务需要保存，必须提供用户开关、脱敏、加密、访问审计和保留周期配置。

### 14.2 查询能力

- 按时间、状态、模型、API 令牌、分组和请求 ID 筛选。
- 支持分页和导出。
- 用户只能查看自己的日志。
- 管理员查看日志时也需要记录审计行为。

## 15. 分组状态与监控

- 定期对渠道和分组执行真实或轻量健康探测。
- 展示最近 60 次探测结果、可用率、平均延迟和可用模型数。
- 状态包括正常、部分异常、不可用和未配置。
- 支持告警恢复通知和抑制重复告警。
- 提供内部 Prometheus 指标或等价监控接口。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/status/groups` | 查询所有分组状态 |
| `GET` | `/api/v1/status/groups/{id}` | 查询分组详情和探测历史 |
| `GET` | `/api/v1/status/overview` | 查询系统状态摘要 |

## 16. 模型市场与创作空间

### 16.1 模型市场

- 查询模型列表、分类、价格、上下文、能力和可用分组。
- 支持文本、图像、视频、音频和向量等分类。
- 区分公开展示状态和实际可调用状态。

### 16.2 创作空间

- 使用当前用户账户余额直接调用模型，不要求用户手动输入 API 令牌。
- 请求仍然必须进入统一网关、计费和日志链路。
- 文本支持流式响应。
- 图像和视频支持任务状态查询。
- 用户刷新页面后可恢复最近任务和对话记录。

## 17. 通知与公告

- 通知类型：余额不足、积分到期、渠道异常、任务完成、套餐变化和系统公告。
- 支持已读、未读和全部已读。
- 首期实现站内通知，邮件和短信作为后续渠道。

## 18. 管理后台功能

### 18.1 用户管理

- 用户查询、状态修改、角色分配和额度调整。
- 管理员不能查看用户密码或完整 API 令牌。
- 手工调整积分必须填写原因并形成账本记录。

### 18.2 模型与渠道管理

- 渠道 CRUD、凭证轮换、连通性测试和启停。
- 模型 CRUD、上游映射和能力配置。
- 分组、倍率、权重和路由规则配置。
- 配置变更需记录前后差异。

### 18.3 财务与运营

- 套餐、价格、活动积分和优惠配置。
- 充值订单、订阅订单和退款记录查询。
- 财务敏感操作需更高权限或二次确认。

### 18.4 系统设置

- 注册开关、邮箱验证开关和默认角色。
- 默认限流、日志保留周期和风控阈值。
- 公告、通知模板和功能开关。

## 19. 核心数据实体

首期建议至少包含以下实体：

| 实体 | 关键字段 |
|---|---|
| `users` | ID、名称、邮箱、密码摘要、状态、角色、创建时间 |
| `auth_sessions` | 用户、刷新令牌摘要、设备、IP、过期时间、撤销时间 |
| `captcha_challenges` | 场景、摘要、失败次数、过期时间、使用时间 |

## 20. 通用接口规范

### 20.1 管理类 API 响应

```json
{
  "success": true,
  "data": {},
  "request_id": "req_xxx"
}
```

错误响应：

```json
{
  "success": false,
  "error": {
    "code": "AUTH_INVALID_CREDENTIALS",
    "message": "邮箱或密码不正确",
    "details": null
  },
  "request_id": "req_xxx"
}
```

OpenAI 兼容接口应尽量保持对应协议的错误响应格式。

### 20.2 分页

- 普通列表使用 `page` 和 `page_size`。
- 大规模日志建议使用游标分页。
- 返回总数时应避免高成本实时统计。

### 20.3 时间与金额

- 时间统一使用 UTC 保存，接口采用 ISO 8601。
- 前端负责按用户时区显示。
- 金额和积分不得使用浮点数直接计算，应使用整数最小单位或 Decimal。

## 21. 建议错误码

| 错误码 | 说明 |
|---|---|
| `AUTH_CAPTCHA_INVALID` | 验证码错误或过期 |
| `AUTH_INVALID_CREDENTIALS` | 邮箱或密码错误 |
| `AUTH_SESSION_EXPIRED` | 会话已过期 |
| `AUTH_ACCOUNT_DISABLED` | 账号不可用 |
| `USER_EMAIL_EXISTS` | 邮箱已注册 |
| `API_KEY_INVALID` | API 令牌无效 |
| `API_KEY_EXPIRED` | API 令牌已过期 |
| `RATE_LIMIT_EXCEEDED` | 请求超过限制 |
| `MODEL_NOT_AVAILABLE` | 模型当前不可用 |
| `GROUP_NOT_AVAILABLE` | 分组当前不可用 |
| `INSUFFICIENT_BALANCE` | 余额不足 |

| `UPSTREAM_ERROR` | 上游服务异常 |
| `VALIDATION_ERROR` | 请求参数错误 |
| `PERMISSION_DENIED` | 权限不足 |
| `INTERNAL_ERROR` | 内部错误 |

## 22. 安全要求

- 所有外部接口强制 HTTPS。
- 密码使用 Argon2id 或 bcrypt，禁止使用可逆加密。
- 上游密钥和支付密钥加密保存，并支持轮换。
- Access Token、Refresh Token、用户 API 令牌和上游 APIKey 禁止写入日志。
- 管理后台支持 MFA 预留。
- 防止 SQL 注入、SSRF、越权、重放、暴力破解和时序攻击。
- 上游 URL 必须执行域名或网段白名单校验，防止 SSRF。
- 上传和媒体 URL 需要类型、大小和来源校验。
- 用户资源查询必须同时校验资源归属。
- 敏感配置的展示、修改和导出写入审计日志。

## 23. 性能与可靠性要求

- 网关服务应支持水平扩容和无状态部署。
- 会话、限流、分布式锁和热点缓存建议使用 Redis。
- 请求日志和用量统计采用异步写入或消息队列削峰。
- 计费账本必须保证幂等和事务一致性。
- 渠道故障不能导致整个网关不可用。
- 支持优雅关闭，避免中断正在处理的流式请求。
- 核心服务需要健康检查和就绪检查接口。

首期建议目标：

- 管理 API P95 响应时间小于 500ms，不含外部支付或邮件服务。
- 网关自身附加延迟 P95 小于 100ms，不含上游模型耗时。
- 认证、账本和 API 令牌操作具备完整审计。
- 核心数据每日备份，并验证恢复流程。

## 24. 开发阶段划分

### P0：可用闭环

- 认证、验证码、注册、登录、密码重置和退出
- 用户资料与登录保护
- API 令牌管理
- 模型、渠道、分组和基础路由
- `/v1/models`、`/v1/chat/completions`
- 基础限流、请求日志和文本 Token 计费
- 钱包余额与积分流水
- 仪表盘基础指标
- 管理员配置渠道和模型

### P1：产品完整度

- Responses、Embedding 和图像接口
- 订阅套餐和订单
- 渠道熔断、备用路由和健康探测
- 完整日志筛选、统计聚合和通知
- 创作空间历史记录
- 管理后台审计和配置变更记录

### P2：规模与高级能力

- 视频、音频和更多异步任务
- 企业组织和子账号
- 高级风控、MFA 和 IP 策略
- 多区域部署、容灾和精细成本优化
- 邮件、短信和 Webhook 通知

## 25. P0 验收标准

后端 P0 完成时，至少满足以下条件：

1. 前端本地认证适配层可替换为真实 API，并完成注册、登录、会话恢复、密码重置和退出。
2. 未登录用户不能访问用户数据接口。
3. 用户可以创建 API 令牌，并通过令牌调用至少一个文本模型。
4. 请求经过鉴权、限流、路由、上游调用、日志和计费完整链路。
5. 同一请求不会重复扣费。
6. 用户可以在控制台查看余额、请求日志和基础统计。
7. 管理员可以配置渠道、模型映射、分组和倍率。
8. 渠道异常时可以自动切换到备用渠道或返回明确错误。
9. 密码、上游 APIKey 和 API 令牌均不会以明文写入数据库或日志。
10. 核心接口具有自动化测试、接口文档、结构化日志和统一错误码。

## 26. 前后端对接优先顺序

建议按照以下顺序进行：

1. `auth/captcha`、注册、登录、刷新令牌、当前用户和退出
2. 模型列表和分组状态
3. API 令牌 CRUD
4. 钱包余额和积分流水
5. 仪表盘统计与调用日志
6. OpenAI 兼容网关接口
7. 套餐、充值和支付
8. 管理后台模型、渠道、路由和计费配置

## 27. 待确认事项

开始后端编码前需要最终确认：

- 后端技术栈与部署环境
- 数据库、Redis 和消息队列选择
- 会话采用 Cookie 还是 Bearer Token
- 是否强制邮箱验证
- 首期需要接入的上游服务商和模型
- 积分单位、定价方式和充值支付渠道
- 是否保存用户提示词与模型输出
- 日志和账单数据保留周期
- 管理后台是否与用户控制台使用同一前端项目
