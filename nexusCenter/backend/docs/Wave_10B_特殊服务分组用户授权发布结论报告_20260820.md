**发布日期**：2026-08-20  
**发布状态**：已正式发布  
**后端版本**：Flyway V17  
**运行容器**：`nexus-api-app-v16-wave10a`（容器名称沿用历史名称，运行 JAR 已升级为 V17 产物）

## 1. 发布目标

完成特殊服务分组按用户授权的完整闭环，同时保证普通分组继续对所有用户开放、内部分组不进入用户端，并让授权边界覆盖查询、API 令牌创建和真实模型调用。

## 2. 已发布业务规则

| 分组受众 | 用户端规则 |
|---|---|
| `all` | 访客和普通用户可以查询；登录用户可以选择该分组创建 API 令牌。 |
| `assigned` | 只有被管理员明确授权且账号仍有效的用户可以查询、创建 API 令牌和调用。 |
| `internal` | 仅管理端使用，用户端不可见。 |

- 管理员只能给 `assigned` 分组分配 active 且未删除的用户。
- 普通分组和内部分组不允许维护用户授权名单。
- 授权关系以 `active/revoked` 状态保留审计历史，不物理删除。
- 撤权后，已有特殊分组 API 令牌在下一次鉴权时立即失效。
- 未授权统一返回 `GROUP_NOT_AVAILABLE`，不向调用方泄露特殊分组是否存在。
- 管理接口只接收用户 ID；授权查询只返回用户 ID、显示名和脱敏邮箱。

## 7. 回滚说明

### 应用快速回滚

当 V17 应用出现阻塞级运行问题时，停止当前容器，将运行 JAR恢复为 `nexus-api-server-before-v17.jar`，再启动容器并验证 readiness。V17 是新增授权表的向前兼容迁移，短时应用回滚可以保留该表，但特殊分组授权功能将不可用。

### 完整数据回滚

如需完整撤销 V17 数据结构和授权数据：

1. 停止应用写入。
2. 先保留当前故障现场备份。
3. 使用 `nexus-before-v17.dump` 恢复正式数据库。
4. 恢复 `nexus-api-server-before-v17.jar`。
5. 启动应用并验证 Flyway V16、readiness、登录、服务分组和模型市场。

禁止只执行回滚 SQL后继续运行 V17 JAR；数据库和应用版本必须作为同一回滚单元处理。

## 8. 运行观察建议

- 观察授权管理接口的 4xx/5xx、数据库授权写入失败和 API 令牌鉴权失败率。
- 重点关注 `GROUP_NOT_AVAILABLE` 的异常突增，排查是否发生误撤权或分组受众配置错误。
- 每日检查应用健康状态和 Flyway 校验；每周抽查授权历史与有效用户状态一致性。
- 日志、监控和审计中继续禁止记录完整邮箱、Authorization、Bearer Token 或上游密钥。
