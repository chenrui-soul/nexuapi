## 1. 目标链路

```text
供应商
  → 维护文本、图像、视频、音频、向量和多模态上游接口
  → 维护供应模型

服务分组
  → 关联已选模型所属供应商
  → 配置供应商级优先级和权重
  → 配置分组专用上游 APIKey
  → 配置价格倍率、模型和容灾路由

用户 API 令牌
  → 用户创建时自主选择一个公开且可路由的服务分组
  → 一把 Key 唯一绑定一个服务分组
  → 网关禁止通过请求头跨分组切换
```

## 2. 已完成内容

### 数据库

- 新增 Flyway V14：`V14__service_group_supplier_resources.sql`。
- 新增 `channels.endpoint_type`，用于区分不同能力类型的上游接口。
- 新增 `api_keys.service_group_id`，并完成历史 API 令牌分组回填和非空约束。
- 新增 `routing_group_suppliers`，维护服务分组与供应商的优先级、权重和状态。
- 新增 `routing_group_supplier_credentials`，保存服务分组下供应商级上游凭证密文。
- 新增回滚说明：`docs/migrations/V14__service_group_supplier_resources_rollback.sql`。
- 新增表和字段均包含中文数据库 COMMENT。

### 后端

- 用户 API 令牌创建和编辑时必须绑定唯一服务分组。
- API 令牌 Principal 携带服务分组 ID，网关缺失分组时 fail closed。
- 网关拒绝 `X-Nexus-Group` 指定与 API 令牌不一致的分组。
- 网关上游凭证优先级为：供应商级分组凭证 → 旧渠道级分组凭证 → 接口默认凭证。
- 服务分组保存时根据所选供应模型自动反查并维护供应商关系。
- 支持供应商级凭证新增、轮换、保留原密钥、停用和接口默认凭证回退。
- 管理端响应、审计和日志只返回脱敏状态，不返回凭证密文或明文。
- 渠道兼容执行层继续保留，支持 `endpoint_type` 和 `supplier_id` 过滤。
- 修复首次创建供应商级分组凭证误走 UPDATE、返回 409 的缺陷。

### 前端

- 用户创建和编辑 API 令牌时必须自主选择公开服务分组。
- API 令牌列表展示绑定的服务分组，完整 Secret 仍只存在于创建成功组件内存。
- 服务分组页面改为供应商级优先级、权重和独立上游 Key 配置。
- 分组独立 Key 只允许写入，不回显。
- 独立“渠道管理”和“渠道模型映射”菜单已收敛到供应商详情。
- 新增供应商上游接口与供应模型维护路由。

## 3. 安全结论

- 分组上游 APIKey 使用 AES-GCM 密文保存于数据库。
- AES-GCM 主密钥、查找 HMAC 密钥和用户 API 令牌 HMAC 密钥均通过环境变量占位，不存入数据库。
- 管理端供应商凭证列表 SQL 不读取密文字段；只有单条写入/轮换路径可读取密文。
- API 令牌和上游 APIKey 不进入管理响应、审计数据或业务日志。
- 前端未发现把 API 令牌或上游 APIKey 写入 localStorage/sessionStorage 的实现。
- 现有模型分组同步 Token 仍按此前用户明确授权保存在 `application.yml`；它不是本轮新增内容，但仍属于待迁移到环境变量或密钥管理服务的已知风险。
