## 2. 根因与修复

模型主表已有 205 条数据，问题不在模型同步本身。用户模型市场和 API 令牌权限目录只接收“服务分组模型目录 + 真实可用路由”的闭合数据；历史服务分组保存链路没有完整恢复渠道模型映射和路由，因此公开目录被正确过滤为空。

本轮发布的新后端 JAR支持管理员保存服务分组配置时统一维护模型目录、渠道模型映射和路由。正式环境通过管理员现有原子配置接口重新保存 `gpt_tj` 分组的 17 个上游开放模型，保留现有分组专用加密凭证，没有直接手工写业务表。

## 5. 用户与管理员职责边界

用户端只处理：选择服务分组、查看该分组真实可调用的模型和价格、选择模型白名单，以及创建和管理自己的 API 令牌。

管理员端负责：供应商关系、上游接口和加密凭证、渠道模型映射和真实路由，以及服务分组价格、受众和开放模型。

系统在后端自动检查管理员配置是否形成可调用闭环。用户请求和响应不包含供应商、渠道、路由、上游地址、上游密钥或供应商成本。

## 6. 边界审查证据

- 用户前端代码对 `/api/v1/admin`、`lib/admin` 和管理组件的依赖命中 0。
- 公开服务分组与模型市场响应字段递归扫描，supplier/channel/credential/route/upstream/cost 命中 0。
- API 令牌写请求只包含服务分组、模型白名单、用户自有配额和安全限制，不接收供应商、渠道、凭证或路由参数。
- 后端按当前用户 ID 限制 API 令牌资源访问，并在 Service/Mapper 内部校验服务分组可见性和真实可路由模型。
