# 前端登录页静态资源 404 修复报告

## 问题结论

登录卡住并非账号、密码、Cookie Session 或后端认证故障。前端切换到 Vinext 0.0.50 生产服务器后，Windows 路径分隔符导致静态资源缓存键错误，登录页引用的 JavaScript 和 CSS 返回 404，验证码与登录客户端逻辑未完成初始化。

## 复现证据

- `GET /login`：HTTP 200。
- `GET /assets/index-D1p117pR.js`：修复前 HTTP 404。
- `GET /assets/index-sUTELuYR.css`：修复前 HTTP 404。
- 浏览器控制台：`Failed to fetch dynamically imported module`。
- 静态缓存查询：URL 键 `/assets/index-D1p117pR.js` 不存在，实际键为 `/assets\\index-D1p117pR.js`。
- 浏览器表现：验证码按钮保持禁用和加载状态。

## 修复方案

修改前端 `scripts/start.mjs`：

1. 继续使用 Vinext 原 `startProdServer`，不重写 SSR 或路由逻辑。
2. 启动前包装 `StaticFileCache.create`。
3. 仅在 Windows 将静态缓存键中的反斜杠替换为 URL 正斜杠。
4. 不修改 `node_modules` 文件，确保依赖重新安装后项目修复仍然存在。

## 验证结果

- `node --check scripts/start.mjs`：通过。
- `npm run lint`：通过。
- `npm test`：39/39 通过，生产构建成功。
- 备用端口生产验证：主 JavaScript HTTP 200，84935 字节；主 CSS HTTP 200，254261 字节。
- 正式 3000 端口：登录页 HTTP 200，主 JavaScript HTTP 200。
- 浏览器：验证码图片可见，刷新按钮可用，登录按钮可用；空表单点击登录后正确显示“请输入 4 位验证码”。
- 后端未改动，正式数据库未改动。

## 回滚

如兼容层引发异常，可恢复旧 `scripts/start.mjs` 并临时使用 `npm run dev -- --port 3000` 恢复本地可用性；回滚后应继续保留本报告，并在 Vinext 升级且官方修复 Windows 缓存键后删除项目兼容层。
